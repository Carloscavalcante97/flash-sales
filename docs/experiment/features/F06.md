# F06: sala de espera

## Contrato da API

- `POST /sales` aceita o campo opcional `"maxActive"` (inteiro de 1 a 10000;
  fora disso → `400`). Quando a venda tem `maxActive`, o `201` e o
  `GET /sales/:id` incluem o campo; sem ele, as respostas não mudam. Venda sem
  `maxActive` não tem sala de espera e se comporta como antes.
- `POST /sales/:id/queue { "buyerId": string }` (mesma validação de `buyerId`
  da F01)
  → `201` com o ticket (formato abaixo) · `404` se a venda não existir ·
  `400` com `buyerId` inválido · `409 { "error": "NO_WAITING_ROOM" }` se a venda
  não tiver `maxActive`. Se o mesmo `buyerId` já tem ticket `WAITING` ou
  `ACTIVE` nessa venda, responde `200` com esse ticket em vez de criar outro.
- `GET /queue/:ticketId` → `200` com o ticket · `404`.
- Formato do ticket, conforme o `status`:
  - `{ "ticketId", "status": "WAITING", "position" }`, em que `position` é 1 +
    o número de tickets `WAITING` à frente;
  - `{ "ticketId", "status": "ACTIVE", "token", "expiresAt" }`;
  - `{ "ticketId", "status": "DONE" }` depois que o token foi usado;
  - `{ "ticketId", "status": "EXPIRED" }` se o token venceu sem uso.
- `POST /sales/:id/orders` numa venda com sala de espera exige o header
  `Queue-Token`. Token ausente, desconhecido, vencido, já usado, de outra venda
  ou de outro `buyerId` → `403 { "error": "INVALID_QUEUE_TOKEN" }`, sem mexer no
  estoque. Token válido → segue como antes (`201` ou `409 SOLD_OUT`), e o token
  passa a usado (`DONE`).
- Com `Idempotency-Key`, a repetição devolve a resposta guardada mesmo que o
  token já tenha sido usado.
- Variável `QUEUE_TOKEN_TTL_MS` (padrão `120000`): validade de um token `ACTIVE`.

## Regras

- **Nunca há mais que `maxActive` tickets `ACTIVE` por venda**, nem sob
  centenas de entradas simultâneas.
- Fila FIFO pela ordem de entrada. A `position` de um ticket nunca aumenta.
- Quando uma vaga abre (token usado ou vencido), o ticket `WAITING` mais antigo
  vira `ACTIVE` em até 2 s, sem depender de outra requisição.
- Pode usar Postgres ou Redis (`REDIS_URL`, padrão `redis://localhost:56379`).
- `:ticketId` com byte NUL, que não seja UUID ou que não exista → `404`.

## Fora do escopo

SSE e tela da fila (extra E1), prioridade, autenticação, sair da fila.
